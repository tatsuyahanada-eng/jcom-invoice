# APP UP FTP Manager

作成した PWA などの成果物を **解凍 → 整理（コピー・貼り付け）→ FTP サーバへアップロード** するためのツール。
スマホと PC の両方で使える PWA と、自分の PC で動かす小さな「中継サーバ」の2つで動きます。

- 解凍に対応: ZIP / LZH(LHA) / TAR / tar.gz / tar.bz2 / tar.xz / RAR(v4・v5) / 7z
  - ZIP・LZH は Windows で作った **日本語ファイル名（Shift_JIS）も文字化けしない** 独自デコーダ
- FTP サーバを複数登録して切り替え（FTPS 推奨・FTP も可）
- 2画面のファイルマネージャ（ローカル ⇔ サーバ）: フォルダ作成・名前変更・削除・コピー／切り取り／貼り付け・フォルダごとアップロード／ダウンロード
- PC では実際のフォルダ（例: `C:\work\site`）を開いて直接読み書き（Chrome / Edge）

---

## 1. 提案: なぜこの構成か

### ブラウザ（PWA）は FTP と直接通信できない
ブラウザには FTP 用の通信手段（TCP ソケット）がありません。どの PWA でも FTP を使うには、
**どこかに中継役が必要** です。ここがセキュリティ判断の分かれ目になります。

| 案 | 中身 | 良い点 | 心配な点 |
|---|---|---|---|
| **A. PWA ＋ 自分の PC の中継サーバ（採用）** | 画面は PWA、FTP 通信は自分の PC の Node.js が担当 | スマホ・PC 共通。中継は自分の手元だけ。第三者のサーバを通らない | 中継 PC を起動しておく必要がある。スマホから使うには Tailscale 等が必要 |
| B. PWA ＋ クラウド上の中継 | 中継をレンタルサーバ等に置く | どこからでも使える | FTP パスワードがクラウドを通過する。公開サーバは攻撃対象になる → **非推奨** |
| C. Android APK（Capacitor 等） | アプリ自身が FTP 通信 | 中継不要。スマホ単体で完結 | Android のみ。ネイティブ部分（FTP プラグイン）の開発・署名・配布管理が必要 |
| D. PC アプリ（Electron） | PC アプリ自身が FTP 通信 | 中継不要 | PC のみ。スマホでは使えない |

**推奨: まず A で運用し、スマホ単体で使いたい場面が多ければ C（APK）を追加。**
画面のコード（`public/`）は Capacitor でそのまま APK に包めるように作ってあり、
FTP 部分だけネイティブに差し替えれば APK 化できます（下の「APK 化」参照）。

### 「PWA はセキュリティが心配」への答え
心配されがちな点と、このツールでの対策:

| 心配 | 対策 |
|---|---|
| FTP パスワードが盗まれる | 端末内に **AES-256-GCM で暗号化** して保存（マスターパスワードから PBKDF2 60万回で鍵を生成）。平文では一切保存しない。「パスワードを保存しない」設定も可 |
| 通信の盗聴 | **FTPS（TLS）を既定**。暗号化なし FTP は警告を出してから接続。証明書の検証も既定で有効 |
| 中継サーバを他人に使われる | 既定で **127.0.0.1（その PC 自身）でしか待ち受けない**。さらにアクセストークン必須（定数時間比較・連続失敗でロック）。接続先ホストの許可リストも設定可 |
| 悪意あるアーカイブ（zip slip 等） | `../` や絶対パスを含む書庫は **展開前に検出して中止** |
| 悪意あるファイル名で画面を乗っ取る（XSS） | ファイル名はすべて文字として表示（HTML として解釈しない）。CSP で外部スクリプト・インライン実行を禁止 |
| FTP コマンド注入 | パス中の改行・NUL を中継サーバで拒否 |
| 放置した端末 | 一定時間（既定10分）操作がないと自動ロックして切断 |
| 外部 CDN の改ざん | 外部から何も読み込まない（解凍用 WASM も同じサーバから配信） |

APK にしても「端末内に暗号化保存」「FTPS」が大事なのは同じです。
**PWA だから危ない、というより「中継をどこに置くか」が本質** で、A 案は中継を自分の手元に限定しています。

## 2. セットアップ

必要なもの: Node.js 20 以上（https://nodejs.org/ja）

### PC だけで使う（いちばん簡単・安全）
1. このフォルダで中継サーバを起動
   - Windows: `start-relay.bat` をダブルクリック
   - Mac / Linux: `./start-relay.sh`
2. 表示された **アクセストークン** を控える
3. ブラウザ（Chrome / Edge 推奨）で `http://localhost:8790/` を開く
4. マスターパスワードを設定 → 設定画面にアクセストークンを貼り付け
5. 「サーバ管理」で FTP サーバを登録 → 選択して「接続」
6. アドレスバーの「インストール」ボタンでアプリとして追加できます

### スマホからも使う（推奨: Tailscale）
スマホのブラウザで暗号化・端末内保存を使うには **HTTPS が必須** です。
いちばん安全で簡単なのは [Tailscale](https://tailscale.com/)（自分の端末だけの VPN）です。

1. PC とスマホに Tailscale を入れて同じアカウントでログイン
2. PC で中継サーバを起動（そのまま 127.0.0.1 のままで OK）
3. PC で `tailscale serve --bg 8790` を実行
4. スマホで `https://<PC名>.<tailnet名>.ts.net/` を開き、「ホーム画面に追加」

インターネットに公開されず、自分の端末からしか届きません。ルータのポート開放は **しないでください**。

> 自前の証明書を使う場合: `TLS_CERT=cert.pem TLS_KEY=key.pem HOST=0.0.0.0 node server/server.js`

### 中継サーバの設定（環境変数）
| 変数 | 既定 | 説明 |
|---|---|---|
| `HOST` | `127.0.0.1` | 待ち受けアドレス。外部に出す場合は必ず HTTPS か VPN で |
| `PORT` | `8790` | ポート |
| `RELAY_TOKEN` | 自動生成 | アクセストークン（16文字以上）。未指定なら `server/.relay-token` に生成・保存 |
| `TLS_CERT` / `TLS_KEY` | なし | 指定すると HTTPS で起動 |
| `FTP_HOST_ALLOWLIST` | なし | 接続を許す FTP ホストをカンマ区切りで限定（例: `ftp.example.com,ftp2.example.com`） |
| `ALLOW_PLAIN_FTP` | `1` | `0` にすると暗号化なし FTP を禁止 |
| `MAX_UPLOAD_MB` | `2048` | 1ファイルの上限 |

## 3. 使い方（よくある流れ）

1. **ローカル** 側で「取り込み」→ 作った `xxx.zip` を選ぶ（PC はドラッグ＆ドロップも可）
2. ZIP を選んで「**解凍**」→ 同名フォルダに展開される
3. 必要なら フォルダ内でファイルを「コピー」→ 別フォルダで「貼り付け」して整理
4. 上で **接続** → サーバ側で目的のフォルダ（例: `/public_html/app`）を開く
5. ローカルでフォルダ／ファイルを選んで「**アップロード →**」
   - 同じ名前があれば確認のうえ上書き

そのほか:
- サーバ上の ZIP を「DL して解凍」→ ローカルに展開
- サーバ側でも コピー／切り取り／貼り付け（切り取りはサーバ内移動）・名前変更・削除
- PC では「ローカルの場所」から **PC のフォルダを開く** と、実際のフォルダを直接操作
- スマホの「アプリ内作業領域」はアプリ専用の保存領域です。端末に保存したいファイルは「端末に保存」
- 設定 →「暗号化バックアップを保存」で、登録したサーバ一覧を別の端末に移せます（同じマスターパスワードで復元）

## 4. 構成

```
ftp-client/
├─ public/               PWA（画面）
│  ├─ index.html, css/, icons/, manifest.webmanifest, sw.js
│  ├─ js/app.js          画面・ファイルマネージャ・転送
│  ├─ js/vault.js        暗号化ストレージ（AES-GCM / PBKDF2）
│  ├─ js/relay.js        中継サーバ API クライアント
│  ├─ js/localfs.js      端末内ファイル操作（OPFS / PC フォルダ）
│  └─ js/archive/        解凍（ZIP・LZH 独自実装、その他は libarchive WASM）
├─ server/
│  ├─ server.js          中継サーバ（basic-ftp）
│  └─ test/              テスト（npm test）
├─ start-relay.bat / start-relay.sh
```

開発: `cd server && npm install && npm test`（テスト用 FTP サーバ込み・14項目）

## 5. 今後の拡張案

- **APK 化（スマホ単体で完結）**: Capacitor で `public/` を包み、`relay.js` と同じ形の
  ネイティブ FTP プラグイン（Android: Apache Commons Net）を用意すれば中継なしで動きます。
  社内配布なら Play ストアを使わず APK 直接配布も可能（署名鍵の管理が必要）。
- **SFTP 対応**: サーバが SSH に対応していれば FTPS よりも設定が簡単で安全。中継サーバに追加可能。
- 差分アップロード（更新されたファイルだけ送る）、アップロード前のバックアップ取得。

## 制約
- 解凍・転送はブラウザのメモリ上で行うため、数 GB 級の書庫は PC での利用を推奨
- RAR / 7z / TAR の日本語ファイル名は UTF-8 で作られたものに対応（Shift_JIS 名は ZIP・LZH のみ対応）
- iPhone（Safari）は PC フォルダを開く機能なし（アプリ内作業領域を使用）
