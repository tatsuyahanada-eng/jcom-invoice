# 運用設計書 — SE歴20年 × AI アプリ制作

> 「現役SE（歴20年）が、本業の生活と両立しながら AI を相棒に PWA / Android アプリを作り、
> それを受注・提供する」ための、毎日のルーティンと仕組みのたたき台です。
> 料金や時間配分は仮の数字なので、実際に回しながら調整してください。

---

## 1. コンセプト

| 項目 | 内容 |
|---|---|
| **誰が** | システムエンジニア歴20年の現役SE。平日は本業、空き時間で AI を使ったアプリ制作 |
| **誰に** | 中小企業・個人事業主・現場の担当者（「IT に詳しい人がいない」「大きなシステム会社に頼むほどではない」） |
| **何を** | Excel・紙・手作業の業務を、PWA（URL を開くだけ）や Android アプリ（社内配布 APK）にする小さな業務アプリ |
| **なぜこの人か** | 20年分の「現場の困りごと」と設計・テスト・運用の経験 × AI で早く安く作る力。AI 任せではなく、SE が設計して確認する |
| **約束すること** | まず小さく試作して見せる。できないこと・AI の限界も正直に言う |

**発信の軸（3本柱）**

1. **SE の日常 × AI** — 本業の中で AI をどう使っているか（ネタ帳から。実体験だけ）
2. **作れるもの** — 開発事例、トレンドからのアプリ案、「あったらいいね」
3. **頼み方がわかる** — PWA と APK の違い、費用感、進め方などの豆知識

アカウント名は、コンセプトが一目で伝わるものに変えることを検討してください（例: 「SE歴20年｜AIでアプリ作る人」「AIアプリ工房｜現役SE」）。
変えたら `config/profile.json` の `displayName` / `handle` も合わせます。

```

 開発事例 ─────────┼─▶ ① 毎日の自動投稿 ─▶ ② 反応・DM ─▶ ③ ヒアリング(30分)
 ニュース/季節 ────┘        ▲                                  │
                            │                                  ▼
 ⑧ 事例として登録 ◀─ ⑦ 保守・改善 ◀─ ⑥ 納品 ◀─ ⑤ 試作→開発 ◀─ ④ 提案・見積
```

| 段階 | 仕組み | 状態 |
|---|---|---|
| ① 発信 | このツール（毎日 20:07 に自動生成・チェック・投稿） | ✅ 構築済み |
| ① ネタ集め | `data/notes.md` に1行メモ → 月・木の「SEの日常」投稿に使われる | ✅ 構築済み |
| ② DM 対応 | 返信テンプレート（README）。24時間以内に返信 | ✅ テンプレあり／手動 |

## 3. 前提と守ること（本業との両立）

- **就業規則の副業規定を確認する**（届出が必要か、禁止業種はないか）。ここが最優先
- **本業の顧客・取引先からは受注しない**。本業と競合する案件も受けない
- **本業の情報は一切発信しない**。ネタ帳にも勤務先・顧客・案件・同僚が特定できることは書かない
  （ツールでも伏せるよう指示し、NG ワードでチェックしていますが、書かないのが一番確実）
- 本業の PC・アカウント・時間を使わない
- 開業届・確定申告・インボイス登録の要否は、売上の見込みに合わせて税理士や税務署に確認する
- **時間予算: 週 5〜8 時間**（平日 1日30分 × 5 ＋ 週末 3〜4時間）。これを超える案件は納期を長めに取る

## 4. ルーティン

### 毎日（合計 20〜30分）

| いつ | やること | 時間 | 仕組み |
|---|---|---|---|
| 朝（通勤・始業前） | **ネタ帳に1行**。昨日 AI で楽になったこと、「これアプリにできそう」と思ったこと | 2分 | スマホの GitHub アプリで `data/notes.md` を編集 |
| 昼休み | 前日の投稿への返信・リアクションに返事 | 5分 | 手動 |
| 20:07 | 投稿 | 0分 | **自動**（確認モード中は下書きだけ作られる） |
| 20:10〜21:00 | 確認モード中: 下書きを見て OK なら publish 実行 | 3分 | GitHub アプリ → Actions |
| 夜 | **DM 確認・返信**（24時間以内が目安）。反応の良かった投稿をメモ | 10〜15分 | 手動 |

### 毎週

| いつ | やること | 時間 |
|---|---|---|
| 土曜 午前 | 受注案件の開発・試作。案件がない週は自分用のアプリを作る（＝次の事例になる） | 2〜3時間 |
| 土曜 午前 | 完成したもの・進んだものを `data/cases.json` に追記 | 10分 |
| 日曜 夜 | **来週の準備**: ネタ帳の未使用メモが2件以上あるか確認／1週間の投稿を見返し、反応の良かったタイプをメモ | 20〜30分 |

### 毎月（月末 1時間）

- 数字を記録（§7 の KPI）
- 投稿タイプの配分（`schedule`）、CTA、ハッシュタグの見直し
- メニュー・料金の見直し
- 費用確認（Claude API・X API）
- Threads のトークン更新（60日ごと）、`blockedTerms` の追加

### 案件ごと

DM → ヒアリング（30分）→ 提案・見積（2〜3日以内）→ 試作（1〜2週）→ 開発 → 納品 → 2週間後にフォロー → 事例化の許可をもらう

## 5. 提供メニュー（たたき台・料金は仮）

| メニュー | 内容 | 期間の目安 | 料金の目安 |
|---|---|---|---|
| 無料相談 | オンライン30分。作れるか・どう作るかを一緒に考える | — | 無料 |
| お試し試作 | 1〜2画面の PWA を試作して、触って判断してもらう | 1〜2週間 | 3〜5万円 |
| 業務アプリ | 数画面の PWA または Android アプリ。データは端末内／スプレッドシート連携など | 3〜6週間 | 10〜30万円 |
| AI 機能の追加 | 文字起こし・要約・分類などを組み込む | +1〜2週間 | +5〜15万円＋API 実費 |
| 保守 | 不具合対応・小さな修正・OS 更新への対応 | 月額 | 5千〜2万円/月 |

- **最初の2〜3件は「モニター価格」**（例: 半額）にして、匿名での事例公開を条件にする → 事例投稿が増える
- お試し試作の代金は、本開発に進んだら本開発の料金から差し引く（頼みやすくする）
- 本業との両立のため、同時に受ける案件は **1件まで**

## 6. ヒアリング項目（DM → 30分の打ち合わせ）

1. 今いちばん困っている作業は何か（誰が・いつ・どのくらいの時間）
2. 今はどうやっているか（紙／Excel／既存システム）。可能ならサンプルを見せてもらう（個人情報は伏せて）
3. 使う人数と端末（Android／iPhone／PC）
4. データの置き場所（端末内でよいか、共有が必要か、社外に出せないデータか）
5. 社内ルール（アプリのインストール可否、クラウド利用の可否）
6. 希望の時期と予算感（未定でも OK）
7. 完成したら何が楽になっていれば成功か

**PWA と APK の選び分け（提案時の目安）**

| 状況 | おすすめ |
|---|---|
| iPhone と Android が混在／PC でも使う／すぐ試したい | PWA |
| Android だけ／カメラ・マイク・バックグラウンド処理・通知をしっかり使う | Android アプリ（APK 直接配布） |

## 7. 数字で見る（KPI）

毎月末に記録します（スプレッドシート等で十分）。

| 段階 | 指標 | 最初の3か月の目安 |
|---|---|---|
| 発信 | 投稿数（自動）／フォロワー数 | 毎日1本／月 +50〜100 |
| 反応 | 返信・保存・プロフィール閲覧 | 伸びた投稿タイプを把握する |
| 問い合わせ | DM 数 | 月 1〜3件 |
| 商談 | ヒアリング実施数 | 月 1件 |
| 受注 | 受注数・売上 | 3か月で1件（モニター価格でも可） |

DM が来ない場合 → CTA の文言・プロフィール・固定ポストを見直す。
反応はあるが DM が来ない場合 → 「お試し試作」の存在を投稿で伝える回数を増やす。

## 8. 進め方（フェーズ）

### フェーズ0: 準備（〜2週間）
- [ ] 副業規定の確認
- [ ] アカウント名・プロフィール・固定ポストを §1 とREADME のテンプレートで整える。DM を開放する
- [ ] `data/cases.json` の事例を確認（出してよいものだけ `publishable: true`）
- [ ] ネタ帳に5件ほどメモを書きためる
- [ ] API キーを登録し、`SNS_MODE=review`（確認してから投稿）で開始

### フェーズ1: 発信を習慣にする（1〜3か月）
- [ ] 毎日のルーティンを回す（確認モード）
- [ ] 2週間たって下書きの質に問題なければ全自動に切り替え
- [ ] 毎週土曜に自分用アプリを1つ進め、事例を増やす
- [ ] ポートフォリオ兼相談受付ページを作る（§9 ①）

### フェーズ2: 最初の受注（3〜6か月）
- [ ] モニター価格で1〜2件受ける → 事例化
- [ ] 見積・契約・請求のテンプレートを固める
- [ ] 反応の良い投稿タイプに配分を寄せる

### フェーズ3: 仕組み化（6か月〜）
- [ ] よく作る機能（入力フォーム・一覧・Excel 出力・APK 自動更新など）をひな形にして、開発時間を短縮
- [ ] 保守契約を積み上げて、毎月の固定収入にする

## 9. これから作る仕組み（優先順）

| # | 仕組み | 目的 | 規模 |
|---|---|---|---|
| ① | **ポートフォリオ兼相談受付ページ**（PWA） | プロフィールのリンク先。事例一覧（`cases.json` から自動生成）＋相談フォーム。これ自体が「PWA の見本」になる | 中 |
| ② | ヒアリングフォーム | DM の後に送るフォーム。§6 の項目を事前に書いてもらい、打ち合わせを短くする | 小 |
| ③ | 見積・請求テンプレート | メニュー表から見積書を作る。既存の経費精算フォームの Excel 出力の仕組みを流用できる | 小 |
| ④ | APK 配布・自動更新のひな形 | 音声文字起こしアプリの自動アップデート機能を共通部品にして、納品を楽にする | 中 |
| ⑤ | 週次レポートの自動作成 | 1週間の投稿一覧・不合格だった日・ネタ帳の残り件数を毎週日曜に自動でまとめる | 小 |
| ⑥ | ネタ帳への追加をもっと楽に | スマホから1行送るだけでネタ帳に追記される仕組み（GitHub Issue などを利用） | 小 |
