# 交通費レシート読み取り

駐車場・高速代などの領収書を写真でまとめて登録し、**その日の交通費を一覧で確認 → Excel/CSVでダウンロード**、
さらに**月単位で集計**できるWebアプリです。
明細は**MySQL に保存され、PCとスマホで同じデータを共有**します。

---

## できること

| 要件 | 対応 |
| --- | --- |
| 撮った写真をまとめてアップロードして一覧表示 | 複数選択・ドラッグ&ドロップ・PDF対応。1枚の写真に複数レシートが写っていても自動で切り分け |
| その日かかった交通費をダウンロード | 「読み取り」タブで日付を選び、Excel / CSV を1クリック出力 |
| 月単位で集計・保存して後から日別/月別にダウンロード | MySQLに保存。「月次集計」タブで日別内訳・月別推移を表示し、月別/期間別/全期間で出力 |
| PCとスマホでデータを共有 | どちらで登録・修正しても、もう一方へ自動で反映されます |

そのほか
- **オフラインでも撮影・入力できます。** 電波が戻った時点で自動的にサーバーへ送信します
- 読み取り結果はすべて表の上で修正でき、修正内容は自動保存＋自動同期されます
- **自信のない項目は黄色く強調**し、行の先頭にマークを付けます（確認すべき箇所がひと目で分かります）
- レシート画像もサーバーに保存できるので、スマホで撮った領収書をPCで確認しながら修正できます
- 明細ごとに担当者を持たせ、担当者別・月別に絞って出力できます
- PWA対応（ホーム画面に追加して、スマホアプリのように使えます）

---

## 使い方

1. **読み取り** タブに領収書の写真（またはPDF）をまとめて投入します。
2. 表に出た内容を確認します。**黄色い項目は自信が低い箇所**なので、必ず目視で確認してください。
3. 「この日をExcel出力」で当日分を、「月次集計」タブで月単位のファイルをダウンロードします。

### 読み取り精度を上げるコツ
- 真上から、影が入らないように撮る（最も効果があります）
- レシート全体が入るように撮る（端が切れていると合計金額を落とします）
- 複数枚を机に並べて1枚で撮ってもOK。重ならないように少し間隔をあけてください
- どうしても精度が足りない場合は、**設定 → 読み取りエンジン → AI解析** に切り替えてください

---

## 2つの読み取りエンジン

| | 端末内OCR（既定） | AI解析 |
| --- | --- | --- |
| 精度 | 印字がはっきりしていれば実用的。かすれた感熱紙・複雑なレイアウトは苦手 | 高い。駐車場名や経路も読み取れる |
| 費用 | 無料 | AIの利用料がかかります |
| 通信 | 初回に言語データを取得したあとはオフライン可 | 毎回必要 |
| 画像の送信先 | どこにも送信しません | AIサービスへ送信します |

AI解析には接続方法が2つあります。

- **サーバー経由（推奨）** … `api/ai-proxy.php` にAPIキーを置き、ブラウザにはキーを保存しません
- **ブラウザから直接** … 端末にAPIキーを保存します。手軽ですが、**その端末を使える人はキーを取り出せます**。
  共有PCでは使わないでください

## サーバーへの設置

### 1. ファイルをアップロード

`receipt-ocr/` フォルダをそのままアップロードします。

```
receipt-ocr/
├── index.html
├── manifest.webmanifest
├── sw.js
├── assets/          … アプリ本体
└── api/             … サーバー側（PHP）
    ├── config.sample.php
    ├── db.php  records.php  image.php  setup.php
    ├── schema.sql
    └── uploads/     … レシート画像の保存先
```

> **HTTPSで公開してください。** カメラ・Service Worker・PWAはHTTPSでないと動作しません（`localhost` は例外）。

### 2. MySQLのデータベースを用意する

レンタルサーバーの管理画面で、**データベースを1つとユーザーを1つ**作成します。

| 設定項目 | 値 |
| --- | --- |
| データベース名 | 任意（例: `xxxxx_keihi`） |
| 文字コード | **utf8mb4**（`utf8` ではなく `utf8mb4`。絵文字や一部の漢字が化けるのを防ぎます） |
| 照合順序 | `utf8mb4_unicode_ci` |
| ユーザー権限 | そのデータベースに対する SELECT / INSERT / UPDATE / DELETE / CREATE / INDEX |

作成時に表示される **ホスト名（MySQLサーバー名）・データベース名・ユーザー名・パスワード** を控えてください。
ホスト名は `localhost` のこともあれば `mysqlXXX.your-server.jp` のようなこともあります。

### 3. 接続情報を書く

`api/config.sample.php` をコピーして `api/config.php` を作り、控えた情報を書き込みます。

```php
<?php
return [
    'db_host'     => 'localhost',      // 管理画面の「MySQLサーバー名」
    'db_port'     => 3306,
    'db_name'     => 'xxxxx_keihi',
    'db_user'     => 'xxxxx_user',
    'db_password' => '（パスワード）',

    'store_images'    => true,         // レシート画像もサーバーで共有する
    'max_image_bytes' => 2097152,
    'access_token'    => '',           // 追加の合言葉（任意）
];
```

### 4. テーブルを作る

ブラウザで **`https://（あなたのサイト）/receipt-ocr/api/setup.php`** を開きます。
必要なテーブルが自動で作成され、設置状況がチェック結果として表示されます。

- 「✓ 準備できています」と出れば完了です
- 「✗」が出た項目の説明どおりに直して、ページを再読み込みしてください
- 自動作成がうまくいかない場合は、phpMyAdmin で **`api/schema.sql`** の内容を実行してください

作られるテーブルは2つだけです。

| テーブル | 役割 |
| --- | --- |
| `receipts` | 明細1件＝1行。削除した明細も `deleted=1` の行として残し、他の端末へ削除を伝えます |
| `sync_state` | 同期用のカウンタ（1行だけ） |

### 5. アプリ側の設定

アプリを開き、**設定 → サーバー** で

1. 「サーバーと同期する」をオンにする
2. 「担当者」に名前を入れる（明細に記録され、担当者別の集計に使えます）
3. 「接続テスト」を押して `✓ 接続できました` を確認する

**PCとスマホの両方で同じ設定にすれば、データが共有されます。**

### 6. アクセス制限（必須）

**`receipt-ocr/` ディレクトリ全体にBasic認証をかけてください。**
認証がないと、URLを知っている人が誰でも明細を読み書きできます。
リポジトリ直下の `.htaccess` と同じ方法で設定できます。

さらに保護したい場合は、`config.php` の `access_token` に推測されにくい文字列を設定し、
アプリの「設定 → サーバー → 合言葉」に同じ値を入れてください（未設定なら空のままで構いません）。

`api/.htaccess` と `api/uploads/.htaccess` で、設定ファイル・データベース・アップロード先での
スクリプト実行をブロックしています。これらのファイルも必ず一緒にアップロードしてください。

## データ共有のしくみ

```
  スマホ                        サーバー                        PC
 ┌────────┐                ┌──────────────┐                ┌────────┐
 │ 撮影   │ ──── 送信 ───▶ │  MySQL       │ ◀─── 送信 ──── │ 修正   │
 │ 入力   │ ◀─── 受信 ──── │  receipts    │ ──── 受信 ───▶ │ 出力   │
 │(端末内 │                │  uploads/    │                │(端末内 │
 │ に控え)│                └──────────────┘                │ に控え)│
 └────────┘                                                └────────┘
```

- 各端末はブラウザ内（IndexedDB）に控えを持つため、**圏外でも撮影・入力できます**
- 通信が戻ると自動で送受信します（起動時・取り込み後・編集後・1分ごと・オンライン復帰時）
- 画面右上のバッジで状態が分かります（同期済み／未送信あり／オフライン／同期エラー）。
  クリックすると即座に同期します
- 同じ明細を両方の端末で直した場合は、**あとで編集したほうが残ります**。
  端末の日時が大きくずれていると意図しない側が残るので、**日時は「自動設定」にしてください**
- 削除は、他の端末にも削除を伝えるため、サーバー上では `deleted=1` の行として残ります

### バックアップ

MySQLのデータは、レンタルサーバーの管理画面（phpMyAdmin のエクスポート等）でバックアップできます。
アプリの **設定 → データの管理 → バックアップを保存** でも、明細をJSONファイルとして書き出せます。

## 開発・テスト

解析まわりはブラウザなしでテストできます。**`parse.js` を触ったら必ず実行してください。**

```bash
node receipt-ocr/tests/parse.test.js
```

ローカルで動作確認する場合（`file://` では一部機能が動きません）:

```bash
cd receipt-ocr && python3 -m http.server 8000
# http://localhost:8000/ を開く
```

## 精度改善のためにやっていること

実際にレシート画像を読ませて確認しながら調整した点です。

**画像側（`image.js`）**
- 撮影画像のEXIF回転を反映（横向き写真がそのまま入ると、ほぼ読めません）
- 長辺1400〜2200pxに正規化（小さすぎても大きすぎても精度が落ちます）
- **Sauvola法による局所二値化**。全体の明るさ調整では、影や照明ムラのある写真に対応できません
- 二値化「後」に射影プロファイル法で傾きを推定して補正。
  グレースケールのまま推定すると、暗い机などの背景がインクとみなされて推定が効きません
- 局所分散から領収書の領域を検出し、複数枚の切り分けと余白の切り詰めを行います

**文字認識（`ocr.js`）**
- ワーカーを1つだけ作って使い回します（画像ごとに作り直すと極端に遅くなります）
- ページ分割モードは `setParameters()` で設定します（`recognize()` の引数では効きません）
- 認識率が低いときはレイアウト（PSM 4）と画像の向き（90/180/270度）を変えて再試行します
- **2パス構成**：日本語モデルは数字を丸囲み数字に誤読しやすく、
  「1,200円」が「⑫⑥⑥円」＝1266になる例を確認しました。丸囲み数字を禁止すると数字は正しく出ますが、
  今度は「年・月・日」が崩れて日付が取れません。そこで
  **通常パスで日付・時刻・種別・名称を、丸囲み数字を禁止したパスで金額を**取り、
  2つが食い違った金額は「要確認」として黄色く表示します

**テキスト解析（`parse.js`）**
- 金額はキーワードの重み付けで選びます。「お預り」「お釣り」「消費税」「ポイント」は除外します
  （元の実装は最初に見つかった金額を採用していたため、預り金を拾うことがありました）
- 日付は 令和/平成・西暦4桁/2桁・月日のみ に対応し、「出庫」「利用日」の近くを優先します
- 半角カナ、丸囲み数字、`O→0` `l→1` などのよくある誤認識を正規化します
- **長音記号「ー」をハイフンに変換しないこと**。変換すると「リパーク」「パーキング」が壊れ、
  種別判定と店名照合に失敗します

## 制限事項

- 端末内OCRは、かすれた感熱紙・手書き・極端に斜めの写真では読み違えます。
  **出力前に表の内容を必ず確認してください。**
- 同じ明細を同時に編集した場合の解決は「あとで編集したほうを採用」です。
  項目ごとの自動マージはしません。
- レシート画像は 1枚あたり サムネイル約10KB＋拡大用約100KB です。
  月100枚なら1年で約130MB。サーバーの容量が心配な場合は
  `config.php` の `store_images` を `false` にしてください（明細のテキストだけを共有します）。
