# 交通費レシート読み取り（サンプルアプリ）

駐車場・高速代などの領収書を写真でまとめて登録し、**その日の交通費を一覧で確認 → Excel/CSVでダウンロード**、
さらに**月単位で集計**できるようにしたWebアプリです。ビルド不要の静的ファイルなので、
レンタルサーバーにフォルダごとアップロードすればそのまま動きます。

---

## できること

| 要件 | 対応 |
| --- | --- |
| 撮った写真をまとめてアップロードして一覧表示 | 複数選択・ドラッグ&ドロップ・PDF対応。1枚の写真に複数レシートが写っていても自動で切り分け |
| その日かかった交通費をダウンロード | 「読み取り」タブで日付を選び、Excel / CSV を1クリック出力 |
| 月単位で集計・保存して後から日別/月別にダウンロード | 端末内データベース(IndexedDB)に保存。「月次集計」タブで日別内訳・月別推移を表示し、月別/期間別/全期間で出力 |

そのほか
- 読み取り結果はすべて表の上で修正でき、修正内容は自動保存されます
- **自信のない項目は黄色く強調**し、行の先頭にマークを付けます（確認すべき箇所がひと目で分かります）
- 明細ごとにレシート画像のサムネイルを保持（クリックで拡大、`📄` で読み取り全文を確認）
- PWA対応（ホーム画面に追加して、スマホアプリのように使えます）
- 任意で PC・スマホ間のデータ同期、JSONバックアップ／復元

---

## 使い方

1. **読み取り** タブに領収書の写真（またはPDF）をまとめて投入します。
2. 表に出た内容を確認します。**黄色い項目は自信が低い箇所**なので、必ず目視で確認してください。
3. 「この日をExcel出力」で当日分を、「月次集計」タブで月単位のファイルをダウンロードします。

### 読み取り精度を上げるコツ
- 真上から、影が入らないように撮る（最も効果があります）
- レシート全体が入るように撮る（端が切れていると合計金額を落とします）
- 複数枚を机に並べて1枚で撮ってもOK。重ならないように少し間隔をあけてください
- どうしても精度が足りない場合は、**設定 → 読み取りエンジン → AI解析** に切り替えてください

## 2つの読み取りエンジン

| | 端末内OCR（既定） | AI解析 |
| --- | --- | --- |
| 精度 | 印字がはっきりしていれば実用的。かすれた感熱紙・複雑なレイアウトは苦手 | 高い。駐車場名や経路も読み取れる |
| 費用 | 無料 | AIの利用料がかかります |
| 通信 | 初回に言語データを取得したあとはオフライン可 | 毎回必要 |
| 画像の送信先 | どこにも送信しません | AIサービスへ送信します |

AI解析には接続方法が2つあります。

- **サーバー経由（推奨）** … `api/ai-proxy.php` にAPIキーを置き、ブラウザにはキーを保存しません
- **ブラウザから直接** … 端末にAPIキーを保存します。手軽ですが、**その端末を使える人はキーを取り出せます**。
  共有PCでは使わないでください

## サーバーへの設置

### 最低限（読み取りと出力だけ使う）

`receipt-ocr/` フォルダをそのままアップロードするだけです。PHPもデータベースも不要です。

```
receipt-ocr/
├── index.html
├── manifest.webmanifest
├── sw.js
└── assets/
```

> **HTTPSで公開してください。** カメラ・Service Worker・PWAはHTTPSでないと動作しません
> （`localhost` は例外）。
> なお、`index.html` をローカルでダブルクリックして開いた場合（`file://`）は、
> Service Worker とサーバー同期が無効になります。動作確認はWebサーバー経由で行ってください。

### 端末間同期を使う場合（任意）

`api/sync.php` を設置します。PHP 8系 + PDO SQLite が必要です。

1. `api/` をアップロード（`api/data/` は自動生成されます。Web実行ユーザーに書き込み権限が必要）
2. アプリの **設定 → PC・スマホ間の同期** に共有キー（6〜40文字の半角英数字）を入れて「今すぐ同期」
3. PCとスマホで同じ共有キーを設定すれば、明細がマージされます

同期されるのは明細のテキストだけで、**写真はサーバーに送られません**。
共有キーを知っている人は同じデータを見られるため、推測されにくい文字列にしてください。

### AI解析をサーバー経由で使う場合（任意）

1. `api/config.php` を作成します（このファイルはGitに入れないでください）

   ```php
   <?php return ['api_key' => 'sk-ant-...'];
   ```

   もしくはサーバーの環境変数 `ANTHROPIC_API_KEY` を設定します。
2. 設定 → 読み取りエンジン → 「AI解析」＋「サーバー経由」を選びます。

`api/.htaccess` で `config.php` とSQLiteファイルへの直接アクセスを拒否しています。
**さらに、このディレクトリ全体にBasic認証をかけてください**（リポジトリ直下の `.htaccess` と同様）。
中継URLは認証がないと誰でも呼び出せてしまいます。

### CDNが使えない環境で動かす場合

既定では pdf.js / tesseract.js / SheetJS をCDNから読み込みます。
社内ネットワーク等で完全に自己完結させたい場合は、`index.html` 冒頭の `window.APP_CDN` に
自サーバー上のパスを設定し、`<script src=...>` も差し替えてください。

## 開発・テスト

解析まわりはブラウザなしでテストできます。**`parse.js` を触ったら必ず実行してください。**

```bash
node receipt-ocr/tests/parse.test.js
```

ローカルで動作確認する場合（`file://` では一部機能が動きません）:

```bash
cd receipt-ocr && python3 -m http.server 8000
# http://localhost:8000/ を開く
```

## 精度改善のためにやっていること

実際にレシート画像を読ませて確認しながら調整した点です。

**画像側（`image.js`）**
- 撮影画像のEXIF回転を反映（横向き写真がそのまま入ると、ほぼ読めません）
- 長辺1400〜2200pxに正規化（小さすぎても大きすぎても精度が落ちます）
- **Sauvola法による局所二値化**。全体の明るさ調整では、影や照明ムラのある写真に対応できません
- 二値化「後」に射影プロファイル法で傾きを推定して補正。
  グレースケールのまま推定すると、暗い机などの背景がインクとみなされて推定が効きません
- 局所分散から領収書の領域を検出し、複数枚の切り分けと余白の切り詰めを行います

**文字認識（`ocr.js`）**
- ワーカーを1つだけ作って使い回します（画像ごとに作り直すと極端に遅くなります）
- ページ分割モードは `setParameters()` で設定します（`recognize()` の引数では効きません）
- 認識率が低いときはレイアウト（PSM 4）と画像の向き（90/180/270度）を変えて再試行します
- **2パス構成**：日本語モデルは数字を丸囲み数字に誤読しやすく、
  「1,200円」が「⑫⑥⑥円」＝1266になる例を確認しました。丸囲み数字を禁止すると数字は正しく出ますが、
  今度は「年・月・日」が崩れて日付が取れません。そこで
  **通常パスで日付・時刻・種別・名称を、丸囲み数字を禁止したパスで金額を**取り、
  2つが食い違った金額は「要確認」として黄色く表示します

**テキスト解析（`parse.js`）**
- 金額はキーワードの重み付けで選びます。「お預り」「お釣り」「消費税」「ポイント」は除外します
  （元の実装は最初に見つかった金額を採用していたため、預り金を拾うことがありました）
- 日付は 令和/平成・西暦4桁/2桁・月日のみ に対応し、「出庫」「利用日」の近くを優先します
- 半角カナ、丸囲み数字、`O→0` `l→1` などのよくある誤認識を正規化します
- **長音記号「ー」をハイフンに変換しないこと**。変換すると「リパーク」「パーキング」が壊れ、
  種別判定と店名照合に失敗します

## 制限事項

- 端末内OCRは、かすれた感熱紙・手書き・極端に斜めの写真では読み違えます。
  **出力前に表の内容を必ず確認してください。**
- データはブラウザ内に保存されます。ブラウザの「閲覧データを削除」で消えるため、
  定期的に **設定 → バックアップを保存** をおすすめします。
- 写真はサーバーに同期されません（端末内のみ）。
