# WorkBase Portal

現地作業に必要な情報（手順・マニュアル・設定ファイル・書類・連絡先）をまとめ、作業の結果を記録して後から探せる業務ポータル（PWA）。
ログイン・権限・作業マスタ・作業記録・ダウンロード用ファイルは、サーバー（PHP + MySQL）に保存します。権限の判定はすべてサーバー側で行います。

```
portal/
  index.html            アプリ本体（1ファイル）
  manifest.webmanifest  ホーム画面へのインストール用
  sw.js                 オフライン対応（アプリ本体をキャッシュ。/api/ はキャッシュしない）
  icons/                ロゴ・アプリアイコン
  api/                  サーバー側（PHP）。logs.php が作業記録
    index.php           API の入り口（ルーティング）
    auth.php            ログイン・ログアウト・パスワード変更
    users.php           ユーザーの登録・権限（管理者のみ）
    data.php            作業・大項目・お知らせ・連絡先、変更履歴
    files.php           ファイルのアップロード（分割）・ダウンロード
    lib.php             共通処理（DB接続・セッション・権限）
    schema.sql          テーブル定義
    migrate.php         初期設定（テーブル・管理者・サンプルデータ）
    seed.json           サンプルの作業データ
    config.sample.php   設定のひな形
  storage/              アップロードされたファイルの置き場（Web から読めない）
    incoming/           FTP で転送した大きなファイルを置くフォルダ（登録は「FTPファイル」の画面）
```

## 動作環境

- PHP 8.1 以上（`pdo_mysql`、`mbstring`）
- MySQL 5.7 以上 / 8.x、または MariaDB 10.3 以上（文字コードは utf8mb4）
- HTTPS で配信（PWA のインストール、ログインの Cookie に必要）

## サーバーの設置

1. データベースとユーザーを作る

   ```sql
   CREATE DATABASE workbase CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
   CREATE USER 'workbase'@'localhost' IDENTIFIED BY '強いパスワード';
   GRANT ALL ON workbase.* TO 'workbase'@'localhost';
   ```
   テーブルを作る間だけ `CREATE` 権限が必要です。作成後は `SELECT, INSERT, UPDATE, DELETE` だけにしても動きます。

2. 設定を書く

   ```
   cp portal/api/config.sample.php portal/api/config.php   # 接続情報などを書き換える
   ```
   `config.php` は Git に含めません。環境変数（`WB_DB_HOST` `WB_DB_PORT` `WB_DB_NAME` `WB_DB_USER` `WB_DB_PASS` `WB_STORAGE_DIR` `WB_INCOMING_DIR`）でも指定できます。

3. 初期設定（コマンドラインから）

   ```
   php portal/api/migrate.php              # テーブル作成・管理者の登録・サンプルの作業データ
   php portal/api/migrate.php --no-sample  # サンプルの作業データを入れずに、空の状態で始める
   php portal/api/migrate.php --seed       # 確認用のデモの作業記録 40 件を追加（本番では使わない）
   ```
   コマンドラインが使えない場合は、`api/schema.sql` を phpMyAdmin などで実行し、管理者は手で登録してください。

4. `portal` フォルダごとサーバーに置く。

### 初期の管理者

| ユーザー名 | 初期パスワード |
|---|---|
| `admin` | `Welsys@1234` |

初期パスワードのままログインすると、画面上部に「パスワードを変更してください」と表示されます。公開前に必ず変更してください（右上のユーザー名 → パスワードを変更）。パスワードを指定して作成する場合は、`WB_ADMIN_PASSWORD='…' php portal/api/migrate.php` とします。

## レンタルサーバーへの設置（ZIP と Web インストーラ）

`python3 tools/build_package.py` を実行すると `dist/workbase-portal-YYYYMMDD.zip` ができます（ビルドごとにセットアップキーが変わります）。

1. ZIP を展開し、`workbase-portal` フォルダの中身を公開フォルダへアップロード
2. レンタルサーバーの管理画面で MySQL データベースを作成
3. `https://<ドメイン>/<設置先>/api/setup.php` を開き、`INSTALL.txt` のセットアップキーと DB 情報を入力
4. 完了すると `api/config.php` が作られ、`setup.php` とキーファイルは自動で削除されます
5. `admin` / `Welsys@1234` でログインし、すぐにパスワードを変更

## FTP で置いたファイルの登録

EXE や OS イメージなど大きなファイルは、FTP で `storage/incoming/`（サブフォルダ可）に置きます。置いたファイルは移動もコピーもしません。
設定の「FTPファイル」画面に、まだ登録していないファイルが一覧で出るので、「登録する」を押して、表示名・説明・**使う作業**（複数可）を指定します。パスを直接入力して登録することもできます。
登録すると、使う作業の「設定データ」に出て、現場の作業ページからダウンロードできます（ログインが必要・途中から再開可能）。
登録を解除しても、FTP のフォルダのファイルは消えません。`storage/incoming/` の外のファイル、`..` を含むパス、リンクは登録できません。

## 現場で作成する書類（様式と記入例）

作業の編集画面の「書類」タブで、報告書・確認書などを登録できます。1つの書類に「様式（記入前の書類）」と「記入例」の2つのファイルと、「記入のポイント」（1行に1つ）を設定します。
記入例を画像（JPG・PNG など）にすると、作業ページに縮小表示され、タップで拡大できます。PDF は新しいタブで開きます。
書類のファイルも「ファイル管理」で一覧でき、使われている間は削除できません。

## 困ったときの連絡先

管理メニューの「困ったときの連絡先」で、相談できる窓口・担当者（電話・メール・受付時間・相談内容）を登録します（変更は編集以上）。
大項目を指定すると、その大項目の作業ページにだけ表示されます。スマホでは電話番号をタップして発信できます。
以前の版で設置したデータベースにも、最初のアクセス時に保存用の表（settings）が自動で追加されます。

## ファイル管理（削除）

管理メニューの「ファイル管理」（サーバー接続時のみ）で、アップロード済みファイルの一覧・ダウンロード・削除ができます。
削除できるのは編集以上。作業から参照されているファイルは削除できません。
「未使用をすべて削除」で一括削除もできます。削除は変更履歴に残ります。

## 変更履歴

設定の「変更履歴」に、作業・大項目・お知らせ・ユーザー・ファイルなどの変更が、いつ・誰が・何をしたかの記録として残ります（2年たったものは自動で消えます）。
**管理者だけ**が、「履歴を削除」から、1年／半年／3か月／1か月より前の履歴、またはすべての履歴を削除できます（サーバー側でも管理者かどうかを確認します）。削除したこと自体は、新しい履歴として残ります。

## 作業の登録（1ページで完結）

設定画面のホームは「登録内容の一覧」です。作業名・型番・ファイル名・マニュアル名で検索でき、大項目や公開状態で絞り込めます。
「新しく登録」を押すと、作業名・大項目・内容・対象機器・作業手順・設定データ・マニュアル・書類・準備／持参品を1ページで入力できます。
「登録」を押すとすぐにTOPページと検索に反映されます（承認の手続きはありません）。準備中の作業は「TOPページに表示する」のチェックを外して保存します。
旧版の「公開承認」の権限を持つユーザーは、自動的に「編集」として扱われます。

## ログインと権限

- ユーザー・パスワード（bcrypt で保存）・権限は MySQL に保存します。ログインはサーバー側のセッション（Cookie）です。
- 画面の表示だけでなく、**API が毎回、権限を判定**します（権限の変更や無効化は、すぐ反映されます）。

  | 権限 | できること |
  |---|---|
  | 閲覧のみ | 公開中の作業の閲覧・ダウンロード、作業記録の登録・閲覧（自分の記録は編集・削除できる）。設定画面は使えません |
  | 編集 | 作業・大項目・お知らせ・連絡先の登録と編集、公開／非公開、削除、ファイルのアップロード（保存するとすぐ現場に反映） |
  | 管理者 | 上記に加えて、ユーザーの登録・権限の変更・パスワードの再設定、変更履歴の削除 |
- ログインに5回失敗すると、15分間ログインできません（総当たり対策）。8時間操作がないとログアウトされます。
- パスワードは、8文字以上で、英小文字・英大文字・数字・記号のうち2種類以上を含めます。

## ファイルのアップロードと上限

ブラウザからのアップロードには、通常、**PHP とWebサーバーの上限**があります（PHP の標準は、1回の送信が 8MB、ファイル1つが 2MB まで）。そのため、このアプリはファイルを小さく分けて送ります。

- ブラウザは、サーバーの `post_max_size` に収まる大きさ（8MB なら約 6MB）に分けて順に送り、サーバーがつなぎ合わせます。途中で切れても、続きから再開できます。
- 1ファイルの上限は、`config.php` の `max_upload_bytes`（初期値 2GB）です。編集画面の「ファイル」タブに、このサーバーの実際の上限が表示されます。
- Nginx などで `client_max_body_size` を小さくしている場合は、`6m` 以上にしてください（小さいと、自動で分割を小さくして送り直します）。
- **EXE など大きなファイル**や、回線が不安定な場所からの転送は、**FTP で `storage/incoming/` に置き**、設定の「FTPファイル」画面で、パスと「使う作業」を登録します（下の「FTP で置いたファイルの登録」）。転送が終わって1分ほど経ってから取り込めます。
- アップロードしたファイルは、`storage/files/` にランダムな名前で保存され、ログインしたユーザーだけがダウンロードできます（途中から再開できます）。閲覧のみの権限では、公開中の作業のファイルだけです。
- `storage/` は、Web から直接読めないようにしてあります（Apache）。可能なら、`config.php` の `storage_dir` で、公開フォルダの外に置いてください。
- どの作業からも使われなくなったファイルは、`php portal/api/migrate.php --purge-orphans` で削除できます（7日以上前のもの）。

## 保護すること

- **Apache**：`api/.htaccess` と `storage/.htaccess` が、`config.php`・`lib.php`・`schema.sql`・`migrate.php` と `storage/` を外から読めないようにしています（`AllowOverride` が有効な場合）。
- **Nginx など**：同じものを拒否する設定を自分で追加してください。

  ```nginx
  location ~ ^/portal/api/(config\.php|config\.sample\.php|lib\.php|auth\.php|users\.php|data\.php|files\.php|migrate\.php|schema\.sql)$ { deny all; }
  location ^~ /portal/storage/ { deny all; }
  ```
- **書き込み**：同一サイトから送る `X-Requested-With: WorkBase` ヘッダーが必須で、Cookie は `SameSite=Lax`・`HttpOnly`（HTTPS では `Secure`）です。SQL はすべてプリペアドステートメントです。
- **変更履歴**：作業・大項目・お知らせ・ユーザーの変更は、サーバーが記録します（画面からは編集・削除できません）。

## API

`health` と `session` 以外は、ログインが必要です。`?r=` の後ろに指定します。

| メソッド | 呼び出し | 内容 |
|---|---|---|
| GET | `health` / `session` | 接続確認／ログイン状態 |
| POST | `auth/login` `auth/logout` `auth/password` | ログイン・ログアウト・パスワード変更 |
| GET | `bootstrap` | 画面に必要なデータ一式（権限に応じて内容が変わる） |
| POST | `data/{task,cat,notices,users}.…` | 作業・大項目・お知らせ・ユーザーの変更（権限はサーバーで判定） |
| POST / GET | `upload/init` `upload/chunk` `upload/finish` `upload/cancel` / `upload/status` | ファイルのアップロード（分割・再開） |
| GET | `files/limits` | 上限の確認 |
| GET / POST | `ext/list` / `ext/save` `ext/delete` | FTP で置いたファイルの登録（パス・使う作業） |
| GET | `files/{id}` `files/x{id}` | ダウンロード（アップロード分 / FTP 登録分。Range 対応） |
| GET | `logs` `logs/{id}` `logs/export` | 作業記録の一覧・検索・詳細・CSV |
| POST | `logs/save` `logs/delete` | 作業記録の登録・変更・削除 |

## 作業記録

「作業記録」タブに、いつ・誰が・どの店舗で・どんな作業をして・結果はどうだったかを残し、後から探せます。

- **記録する内容**：作業日、店舗名、作業（登録済みの作業から選ぶか、自由入力）、作業結果（完了／一部未完了／中止）、結果・メモ、添付（作業報告書・チェックシートの写真、PDF）。
- **担当者は、ログインしているユーザーの名前が自動で入ります**（画面からは変えられません。サーバーが、ログインの情報から記録します）。
- **添付**は画像（JPG・PNG・GIF・WebP）と PDF。1ファイル 30MB まで、1件の記録に 20 件まで。スマホの写真は、画面側で長辺 1800px の JPEG に縮小してから送ります。ファイルの中身（先頭の印）もサーバーで確認し、画像・PDF 以外は受け付けません。
- **検索**：店舗名・担当者（名前・ユーザー名）・作業名・メモをキーワードで（空白で区切ると、すべてを含むもの）。期間・作業・担当者・結果での絞り込みと、CSV の書き出しもできます。
- **権限**：ログインしている人は誰でも、記録の登録と、全員の記録の閲覧ができます。変更・削除できるのは、記録した本人と、編集以上の権限の人です。記録を削除すると、添付も一緒に削除されます。
- 登録には通信が必要です（オフラインでは登録・検索できません）。
- 以前の版の「チェックシート」の画面と、その完了記録（テーブル `work_records`）は廃止しました。古いテーブルはデータベースに残りますが、画面には出ません。

## サーバーがない場合（デモ）

サーバーに接続できず、この端末で一度もログインしていない場合は、ログインなしのデモ画面で動きます。権限の違いは、右上のユーザー名から切り替えて確認できます。データはこのブラウザ内にだけ保存されます。

## PWA（アプリとして使う）

スマホのブラウザのメニューから「ホーム画面に追加」（iPhone は共有ボタンから）。一度ログインした端末は、通信できなくても、最後に読み込んだ内容を表示できます（変更の保存はできません）。画面を更新して配信するときは、`sw.js` 先頭の `VERSION` を上げてください。

## ローカルでの確認

```
WB_DB_PASS=パスワード php -S localhost:8000 -t portal
```
http://localhost:8000/ を開き、`admin` でログインします。
